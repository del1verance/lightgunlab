## What exists (v0.3.0, all hardware-validated on the bench)

Single-player is DONE and validated on real Sinden + GUN4IR hardware: USB detection
(`LightgunDetection.cpp`), startup gun picker → aim test range (`LightgunCalibrationScreen`) with a
6-round `ULightgunWeapon` (ammo gate: live rounds fire recoil, empty dry-fires with NO recoil),
reload via offscreen shot / any non-trigger button / any key, per-gun recoil backends
(`RecoilBackends.cpp`), Sinden border widget, MAME-compatible outputs. Aim in 1P = the merged OS
cursor. **Do not regress any of this — 1P keeps its current code path untouched.**

## Bench laws (violating these re-fights battles we already won)

1. **Sinden TCP** (its software's recoil server, localhost:13000): send `J1` before anything else,
   pace commands ≥200ms apart (`SindenCommandGapMs`), collapse queued fire runs into `T<count><ms>`
   bursts, and keep **exactly ONE connection process-wide** — connection churn or merged messages
   wedge the server until the software restarts. Never start it with the `tcpserver` launch arg.
2. **GUN4IR** enumerates across `2341:804x` (bench gun = `8046`), COM serial `S6`→`F0.2.1`→`E`.
3. Enter game control at gun **selection**, not first fire (init handshake must drain early).
4. Rapid trigger input arrives partly as **double-click events** in Slate; the raw-input path below
   must not reintroduce lost shots (raw input has no double-click synthesis — an advantage).
5. Widget trees build in `NativeOnInitialized` (never `NativeConstruct`); headless guards via
   `FApp::CanEverRender()`.

## The feature

Two lightguns on the same PC at the same time, ANY mix (Sinden+GUN4IR, two Sindens, gun+desktop
mouse). Decisions already made with the user:

- **Startup panel**: a "One player ‖ Two players" toggle button at the top. In 2P mode, TWO gun
  boxes (Player 1 / Player 2), each a dropdown of detected devices; the same physical device cannot
  be selected in both. Confirm drops into the same test range.
- **Desktop mouse is a valid P2 pick** (aim-only, no recoil hardware) — listed as "Desktop mouse
  (aim only)". Great for dev and one-gun households.
- **Range in 2P**: two crosshairs — **P1 blue, P2 red** (arcade convention; expose both colors as
  config settings) — two ammo pip rows + per-player status/counters, hit rings tinted per player,
  two independent `ULightgunWeapon` instances. Range stays home base (no exit).
- **Reload routing in 2P**: per-gun. Each gun's own non-trigger buttons (and its offscreen shot)
  reload only that player. Gun buttons that present as keyboard keys (GUN4IR, Sinden) must be routed
  per-device via raw keyboard input. A keyboard that doesn't correlate to either gun (the desk
  keyboard) reloads **P1**.
- **Border**: if EITHER selected gun is a Sinden, show the border (it's global/topmost already).

## Technical plan

### Raw input router (the core new piece)

Stock UE merges all mice; two aim points require Windows Raw Input. New Windows-only class (own
files, pattern-match `MameWindowBroadcaster` for platform guards):

- `RegisterRawInputDevices` for mouse (usage page 0x01, usage 0x02) AND keyboard (0x01/0x06) with
  `RIDEV_INPUTSINK` targeting the game window; process `WM_INPUT` via an `IWindowsMessageHandler`
  registered through `FWindowsApplication::AddMessageHandler` (cast
  `FSlateApplication::Get().GetPlatformApplication()`).
- Per event: `RAWINPUTHEADER.hDevice` → `GetRawInputDeviceInfo(RIDI_DEVICENAME)` → the device path
  embeds `VID_xxxx&PID_xxxx` → correlate to the player's selected `FDetectedLightgun` (cache the
  hDevice→player map; rebuild on `WM_INPUT_DEVICE_CHANGE` or rescan).
- Mice: `MOUSE_MOVE_ABSOLUTE` gives 0–65535 normalized coords (divide by 65535, multiply by
  viewport size; handle `MOUSE_VIRTUAL_DESKTOP` by mapping through the virtual-screen rect and
  clamping to the game window). Desktop-mouse-as-gun sends `MOUSE_MOVE_RELATIVE` — accumulate into
  a clamped position instead. Button flags (`RI_MOUSE_LEFT_BUTTON_DOWN`, right, middle, X1/X2) become
  per-player trigger/aux events.
- Keyboards: `RAWKEYBOARD` per hDevice — correlated keyboards route reload to their player;
  uncorrelated → P1. Ignore key repeats.
- Identical-PID pairs (e.g. two GUN4IRs both `8046`): hDevice still distinguishes them, but mapping
  gun-A-the-mouse to gun-A-the-COM-port is ambiguous — correlate by USB parent/container path prefix
  where possible, and add a small "Swap P1↔P2" button on the range as the pragmatic fallback.

### Subsystem refactor (per-player slots)

`ULightgunSubsystem` currently holds one `ActiveGunIndex` + one backend. Generalize to two player
slots (keep the public 1P API working — existing calls route to P1): per-slot gun + backend +
`SelectGunForPlayer(Player, Index)`, per-slot `FireRecoil/NotifyEmpty/SetAmmo`. Outputs already
prefix `P{n}_` — emit per player.

**Sinden backends MUST share one TCP connection.** Restructure `FSindenTcpBackend` into a shared
connection (one socket, one pump, one pacing queue) with per-player command prefixes (`1A`/`2A`…).
Two Sindens = two prefixes, one socket. Which physical Sinden is "1" vs "2" follows the software's
Lightgun A/B assignment — surface a note in the UI and let Swap fix mismatches. Serial guns get one
`FSerialRecoilBackend` per COM port as today.

### Range in 2P

In 2P the range takes aim + trigger + reload exclusively from the raw router (ignore Slate
mouse-down/keys for gameplay to avoid double-fires from the merged cursor — but keep the two Slate
buttons clickable via the merged cursor, and keep 1P mode exactly on today's Slate path). Corner
detection for offscreen shots applies per-device in raw coordinates.

### Settings additions

`CrosshairColorP1` (default blue), `CrosshairColorP2` (default red), `bAllowMouseAsGun` (default
true). Persist the 1P/2P choice and both gun picks.
